คู่มืออัปเดตโค้ดและ Docker Images ของ FarmIQ iot-layer หน้างาน

คู่มือนี้สรุปขั้นตอนใช้งานจริงสำหรับการนำ โค้ด iot-layer เวอร์ชันใหม่ และ Docker images ที่ export ไว้ล่วงหน้า ไปอัปเดตเครื่องหน้างานแบบ offline หรือกึ่ง offline โดยอิงจาก iot-layer/README.md, scripts/deploy.ps1, scripts/deploy.sh และชุดไฟล์ export ปัจจุบัน

อัปเดตล่าสุด: Thursday, August 20, 2026
เหมาะกับ: หน้างาน / field deploy
ใช้กับ export ชุด: 2026-08-16
ประเด็นสำคัญ: การ docker load อย่างเดียว ไม่พอ สำหรับ iot-layer ชุดนี้ เพราะหลาย service mount โฟลเดอร์ source จากเครื่องหน้างานเข้า container โดยตรง ดังนั้นถ้าจะอัปเดตจริง ต้องอัปเดตทั้ง source code และ docker images
หมายเหตุสำหรับเครื่องหน้างาน Ubuntu Linux: ใช้งานได้จริง แต่ต้องใช้ ./scripts/deploy.sh ไม่ใช่ .\scripts\deploy.ps1 ตัว action หลักเหมือนกันคือ core, full, smoke, status, logs, และ down

0. ถ้าเครื่องหน้างานเป็น Ubuntu Linux ให้ใช้คำสั่งชุดนี้

คู่มือนี้มีตัวอย่างคำสั่งแบบ Windows อยู่หลายจุด เพราะตอนแรกจัดทำจากเครื่องพัฒนา Windows แต่สำหรับเครื่องหน้างาน Ubuntu ให้ยึด scripts/deploy.sh เป็นหลัก
งานที่ต้องทำ Windows Ubuntu Linux
เปิด core .\scripts\deploy.ps1 -Action core ./scripts/deploy.sh core
เปิด full .\scripts\deploy.ps1 -Action full ./scripts/deploy.sh full
เปิด smoke .\scripts\deploy.ps1 -Action smoke ./scripts/deploy.sh smoke
ดูสถานะ .\scripts\deploy.ps1 -Action status ./scripts/deploy.sh status
ดู logs .\scripts\deploy.ps1 -Action logs -Service weight-vision-service ./scripts/deploy.sh logs weight-vision-service
ปิด stack .\scripts\deploy.ps1 -Action down ./scripts/deploy.sh down
สิ่งที่ต้องมีบน Ubuntu: bash, docker, และ docker compose ถ้ายังรัน script ไม่ได้ ให้ลอง chmod +x ./scripts/deploy.sh ก่อนหนึ่งครั้ง

1. สิ่งที่ต้องเตรียมก่อนออกหน้างาน

  • โฟลเดอร์ iot-layer เวอร์ชันใหม่ที่ต้องการ deploy
  • โฟลเดอร์ iot-layer/docker-exports/2026-08-16 ที่มีไฟล์ .tar
  • ไฟล์ iot-layer/weight-vision-service/.env ที่ใช้จริง
  • ไฟล์ iot-layer/.env ถ้าจะเปิด live capture
  • config กล้อง, RTSP, scale, และไฟล์ใน camera-config ถ้ามีค่าเฉพาะไซต์
  • พื้นที่ disk ว่างเพียงพอสำหรับ image ขนาดใหญ่ โดยเฉพาะ weight-vision-capture
หมายเหตุ: ชุด export ปัจจุบันมี image อย่างน้อย 5 ตัว: ui-app, weight-vision-service, weight-vision-calibrator, weight-vision-capture, และ weight-vision-capture-smoke

2. ตัดสินใจก่อน deploy

เป้าหมาย Action ที่ใช้
เปิด UI + calibrator + service โดยยังไม่ใช้ hardware capture core
เปิดระบบเต็มรวมกล้อง RTSP และตาชั่ง full
เช็กแค่ container startup และ model runtime แบบไม่พึ่ง hardware smoke
คำแนะนำใช้งานจริง: ถ้าหน้างานมีความเสี่ยงสูง ให้เริ่มจาก core ก่อนเสมอ เมื่อ core stack ขึ้นครบแล้ว ค่อยขยับไป full

  4. คัดลอกโฟลเดอร์ docker-exports ไปไว้บนเครื่องหน้างาน

    แนะนำให้คงโครงสร้างเดิมไว้ เช่น iot-layer\docker-exports\2026-08-16

    ถ้าไม่แน่ใจ เริ่มที่ core ก่อน แล้วค่อยไป full

3A. ถ้าเครื่องเดิมมีการรันโค้ดอยู่ ต้องจัดการอย่างไร

หลักการสำคัญ: เครื่องเดิมที่กำลังรันอยู่ให้ถือว่าเป็นระบบใช้งานจริงชั่วคราว ดังนั้นก่อนอัปเดตต้องทำให้สามารถ ย้อนกลับ ได้เสมอ
ข้อผิดพลาดที่เจอบ่อย: เอาโค้ดชุดใหม่ไปเปิดจาก อีกโฟลเดอร์หนึ่ง ทั้งที่ stack เดิมยังรันอยู่ ผลคืออาจเกิด container คนละ compose project วิ่งซ้อนกัน, port ชนกัน, หรือแย่ง camera/scale device เดียวกัน ดังนั้นต้องหาให้ชัดก่อนว่า stack เดิมรันมาจากโฟลเดอร์ไหน แล้วค่อยหยุดจากโฟลเดอร์นั้นก่อนเสมอ
  1. เก็บหลักฐานสถานะเดิมก่อนแตะอะไร

    จดว่า service ไหนขึ้นอยู่, ใช้ไฟล์ env อะไร, และมีปัญหาค้างอยู่หรือไม่

    cd D:\path\to\iot-layer
.\scripts\deploy.ps1 -Action status
.\scripts\deploy.ps1 -Action logs -Service weight-vision-service
.\scripts\deploy.ps1 -Action logs -Service weight-vision-calibrator
.\scripts\deploy.ps1 -Action logs -Service weight-vision-capture
  2. ถ้าไม่แน่ใจว่า stack เดิมรันจากโฟลเดอร์ไหน ให้หา working directory ก่อน

    ขั้นตอนนี้สำคัญมากในเครื่องที่มีหลายชุดโค้ดหรือเคย copy โฟลเดอร์ไว้หลายเวอร์ชัน ให้ดูทั้ง compose label และ mount path ของ container เดิมก่อน 

    docker compose ps --all

docker inspect --format "{{ index .Config.Labels \"com.docker.compose.project.working_dir\" }}" iot-layer-weight-vision-service-1

docker inspect --format "{{ range .Mounts }}{{ .Source }} -> {{ .Destination }}{{ println }}{{ end }}" iot-layer-weight-vision-service-1

    ถ้าผลลัพธ์ชี้ไปที่โฟลเดอร์อื่น เช่น D:\deploy\iot-layer ให้ไปหยุด stack จากโฟลเดอร์นั้นก่อน ไม่ใช่จากโฟลเดอร์ใหม่ที่เพิ่ง copy เข้าเครื่อง

  3. backup โฟลเดอร์เดิมทั้งชุดก่อนอัปเดต

    แนะนำให้ copy โฟลเดอร์ iot-layer เดิมทั้งก้อนไปไว้เป็น backup เช่น iot-layer_backup_2026-08-20 เพื่อให้ rollback ได้เร็วที่สุด

  4. backup ไฟล์ config เฉพาะไซต์แยกอีกชั้นหนึ่ง
    • iot-layer\.env
    • iot-layer\weight-vision-service\.env
    • ไฟล์ใน camera-config ที่อาจถูกปรับเฉพาะหน้างาน
  5. หยุด stack เดิมให้เรียบร้อยก่อนทับ source code

    ขั้นตอนนี้สำคัญมาก เพราะ compose ชุดนี้ mount source code เข้ container โดยตรง ถ้าไม่หยุดก่อนแล้ว copy ทับ จะตรวจว่า container ใช้โค้ดเวอร์ชันไหนอยู่ได้ยากมาก 

    cd D:\path\to\iot-layer
.\scripts\deploy.ps1 -Action down
  6. ตรวจให้แน่ใจว่า container เดิมหยุดจริง 
    .\scripts\deploy.ps1 -Action status

    ถ้ายังมี container เก่าไม่ยอมลง ให้ตรวจชื่อ service และ logs ก่อน อย่าเพิ่งลบแบบเดาสุ่ม

  7. เลือกวิธี cutover ให้ชัด: ทับโฟลเดอร์เดิม หรือสลับไปโฟลเดอร์ใหม่

    ถ้าหน้างานต้องการความเสี่ยงต่ำสุด แนะนำให้ ใช้โฟลเดอร์เดิม แล้ว backup ออกก่อน เพราะ compose path, env path และ shortcut เดิมมักยังใช้ได้ต่อทันที

    • แบบ A แนะนำ: backup โฟลเดอร์เดิม แล้ว copy โค้ดใหม่ลง path เดิม
    • แบบ B ใช้ได้: เตรียมโฟลเดอร์ใหม่ แต่ต้อง down stack เดิมก่อน และต้องแน่ใจว่าหลัง cutover ทีมจะสั่งงานจากโฟลเดอร์ใหม่เท่านั้น
  8. ค่อยอัปเดต source code และโหลด images ใหม่

    หลัง stack เดิมลงแล้ว จึงค่อย copy source ใหม่ทับ หรือสลับไปใช้โฟลเดอร์เวอร์ชันใหม่ จากนั้นค่อยทำ docker load และ deploy ตาม flow ปกติ

  9. ถ้าอัปเดตแล้วมีปัญหา ให้ rollback แบบเร็ว

    ใช้ backup folder และ env เดิมคืนกลับ แล้ว deploy ใหม่ด้วยชุดเดิมก่อน เพื่อให้หน้างานกลับมาใช้งานได้เร็วที่สุด

แนวทางที่ปลอดภัยที่สุด: ถ้าเวลาและพื้นที่ disk พอ ให้เก็บทั้ง source code เดิม และ docker images เดิม ไว้ก่อนอัปเดต จะช่วยให้ rollback ได้เร็วที่สุด
ตัวอย่างลำดับงานที่แนะนำสำหรับเครื่องเดิมที่มี stack รันอยู่แล้ว 
1. เข้าไปที่โฟลเดอร์ที่ stack เดิมใช้งานจริง
2. รัน .\scripts\deploy.ps1 -Action status
3. backup .env, weight-vision-service\.env และ camera-config
4. รัน .\scripts\deploy.ps1 -Action down
5. ยืนยันว่า container เดิมหยุดแล้ว
6. backup โฟลเดอร์ iot-layer เดิมทั้งก้อน
7. copy โค้ดใหม่ลง path เดิม หรือเตรียม path ใหม่ให้ชัดเจน
8. docker load images จาก docker-exports
9. รัน .\scripts\deploy.ps1 -Action core
10. ตรวจ logs และ UI
11. ถ้า core ผ่าน ค่อยรัน .\scripts\deploy.ps1 -Action full

6. จุดที่ต้องระวังมากที่สุด

1. weight-vision-capture จะไม่ขึ้นถ้าใช้แค่คำสั่ง core
เพราะใน compose ปัจจุบัน service นี้อยู่หลัง profile capture ดังนั้นต้องใช้ flow full หรือสั่งพร้อม --profile capture
2. docker load ไม่ได้แทนการอัปเดต source code
ชุด iot-layer นี้ mount source code จากเครื่องเข้า container โดยตรง ดังนั้นถ้าโฟลเดอร์หน้างานยังเก่า service หลายตัวจะยังทำงานด้วยโค้ดเก่าแม้ image จะใหม่แล้ว
3. ค่า SCALE_PORT ต้องตรงกับเครื่องจริง
ในไฟล์ iot-layer/.env ตอนนี้มีค่า SCALE_PORT=/dev/ttyUSB0 และ SCALE_DEVICE=/dev/ttyUSB0 ซึ่งใช้ได้ใน Linux node ที่มี device นี้จริงเท่านั้น ถ้าเครื่องหน้างานเป็น Windows หรือใช้ serial port คนละชื่อ ต้องแก้ก่อนสั่ง full
4. ถ้า full ไม่ขึ้น ให้สงสัย .env ก่อน
โดยเฉพาะค่า RTSP, network route, ตำแหน่ง maps file, และ serial scale
5. อย่าทับ source code ใหม่ขณะ container เดิมยังวิ่งอยู่
เพราะ stack นี้ bind mount โฟลเดอร์ ./:/workspace/iot-layer เข้า container โดยตรง ถ้าแก้หรือ copy ทับระหว่างรันงาน จะทำให้ trace เวอร์ชันยากและ rollback เสี่ยง
6. อย่าเปิด stack ใหม่จากคนละโฟลเดอร์ ถ้ายังไม่ได้ down ของเดิม
แม้ image จะชื่อเดียวกัน แต่ถ้ารันจากคนละ working directory ก็อาจกลายเป็นคนละ compose project ได้ ทำให้ port ชนกันหรือ service แย่ง hardware ตัวเดียวกัน

7. เช็กลิสต์ก่อนสั่ง full

หัวข้อ ต้องเช็กอะไร
RTSP RTSP_IP_LEFT, RTSP_IP_RIGHT, RTSP_USER, RTSP_PASS, RTSP_STREAM_PATH
Scale SCALE_PORT, SCALE_BAUD, และ device path/COM port ต้องมีอยู่จริงบนเครื่อง
Maps MAPS_PATH ต้องอ้างถึงไฟล์ calibration ที่มีจริง
Service connectivity weight-vision-service/.env ต้องชี้ edge endpoint, tenant, และ network settings ถูกต้อง
Disk ต้องมีพื้นที่ว่างพอสำหรับ images และ container logs

8. วิธีเดินงานที่ปลอดภัยที่สุด

  1. โหลด image ให้ครบด้วย docker load
  2. อัปเดต source code โฟลเดอร์ iot-layer ให้เป็นเวอร์ชันใหม่
  3. สั่ง .\scripts\deploy.ps1 -Action core
  4. ตรวจว่า ui-app, weight-vision-calibrator, weight-vision-service ขึ้นครบ
  5. ถ้า core ผ่าน ค่อยเช็ก .env ฝั่ง capture อีกรอบ
  6. จึงค่อยสั่ง .\scripts\deploy.ps1 -Action full
  7. ถ้า live capture มีปัญหา ให้ถอยกลับมาใช้ core เพื่อให้ระบบส่วนอื่นยังทำงานได้ก่อน
แนวทางนี้ช่วยลดความเสี่ยงที่หน้างานจะล้มทั้งชุด เพราะแยกปัญหา core services ออกจากปัญหา camera/scale hardware ได้ชัดกว่า

10. สรุปสั้นสำหรับทีมหน้างาน

  • ถ้าเครื่องเดิมยังรันอยู่ ให้เก็บสถานะเดิมและ backup ก่อนทุกครั้ง
  • หาให้ชัดก่อนว่า stack เดิมรันมาจากโฟลเดอร์ไหน แล้ว down จากโฟลเดอร์นั้นก่อน
  • หยุด stack เดิมก่อนค่อย copy source code ใหม่ทับ
  • เอาไปทั้ง source code ใหม่ และ docker-exports
  • backup .env ของหน้างานก่อนทุกครั้ง
  • ถ้าเครื่องหน้างานเป็น Ubuntu ให้ใช้ ./scripts/deploy.sh เป็นหลัก
  • เริ่มจาก core ก่อน ถ้าไม่จำเป็นอย่าเริ่มด้วย full
  • weight-vision-capture ต้องใช้ profile capture
  • ถ้า full ล้ม ให้เช็ก RTSP_*, SCALE_PORT, และ MAPS_PATH ก่อนเป็นอันดับแรก

เอกสารนี้ตั้งใจให้เปิดอ่านหน้างานได้ทันทีแบบ offline และใช้ร่วมกับไฟล์ใน iot-layer/README.md, scripts/deploy.ps1, scripts/deploy.sh, และ iot-layer/docker-exports/2026-08-16/README.md
