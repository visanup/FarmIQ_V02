ข้อสรุปสั้นที่สุด

สมมติฐาน “interface ส่งค่าเป็น lb แต่ระบบตีความเป็น kg” มีน้ำหนักมากและอธิบายเคสหนักผิดปกติได้ดี โดยเฉพาะค่า 26.30 - 26.65 ในช่วง 2026-05-14 ถึง 2026-05-15 เพราะเมื่อแปลง lb -> kg แล้วจะกลับมาอยู่แถว 11.9 - 12.1 kg ซึ่งใกล้กับน้ำหนักรวมของไก่ 5 ตัวตามมาตรฐานมาก

แต่ยังสรุปว่าเป็นสาเหตุเดียวไม่ได้

แม้สมมติฐานเรื่อง lb interpreted as kg จะลดความขัดแย้งของข้อมูลลงอย่างชัดเจน แต่ยังอธิบายทุก session ไม่หมด จึงยังต้องเก็บสาเหตุอื่นไว้พร้อมกัน เช่น serial stale/carry-over, tare/zero ไม่จริง, residual load บนแท่น และบางเคสมี metadata ฝั่ง vision ผิดปกติร่วมด้วย

4) หลักฐานที่สนับสนุนสมมติฐาน lb interpreted as kg

  • เคสหนักผิดปกติช่วง 26.30 - 26.65 ในวันที่ 2026-05-14 ถึง 2026-05-15 จะกลับมาอยู่แถว 11.7 - 12.1 kg หลังแปลง ซึ่งแทบพอดีกับ 5 ตัวตามมาตรฐาน
  • ในชุดใหญ่ ระดับ session ถ้าอ่านเป็น kg ตรงๆ จะมีถึง 88.2% ที่หนักเกิน 5 ตัว แต่ถ้าแปลงจาก lb ก่อนจะลดเหลือ 45.5%
  • ภาพตัวอย่างจากกลุ่มน้ำหนักสูงสุดใน workbook ดูใกล้เคียงกับ “ประมาณ 4-5 ตัวบนแท่น” มากกว่า “8-10 ตัวบนแท่น”
  • โค้ดรับค่าน้ำหนักฝั่ง capture parse แค่ตัวเลขตัวแรกจาก serial line และไม่ได้ validate หน่วยก่อนใช้เป็น kg

5) หลักฐานที่ยังขัดกับสมมติฐาน lb อย่างเดียว

  • แม้แปลงจาก lb แล้ว ยังมีอีกจำนวนหนึ่งที่ดูหนักเกินกว่าจำนวนตัวที่คาดได้
  • เคส 20260520_171813.json ไม่ได้ชี้ขาดเรื่องหน่วยชัดเท่ากลุ่ม 25-26
  • บาง metadata มีปัญหาฝั่ง vision ร่วมด้วย เช่น 20260515_003842.json ซึ่งมี mask/geometry เพี้ยน
  • ชุด workbook ใหญ่เป็นข้อมูลถึง 2026-05-08 จึงเป็นหลักฐานเชิง pattern ไม่ใช่ proof ตรงของเคส production วันที่ 2026-05-14 ถึง 2026-05-20

6) สาเหตุอื่นที่ยังต้องคงไว้

สาเหตุ ทำไมยังน่าสงสัย ความสัมพันธ์กับเรื่อง lb
Serial stale / carry-over มีโอกาสใช้ค่าน้ำหนักล่าสุดซ้ำ หากรอบนั้นไม่ได้มี byte ใหม่เข้ามา แต่ state เดิมยังถูกมองว่านิ่ง เป็นสาเหตุร่วมได้ แม้ interface จะเป็น lb จริงก็ตาม
Tare/zero ไม่จริง ถ้าแท่นไม่คืนศูนย์หรือมี residual load จะทำให้น้ำหนักรวมสูงกว่าความจริง เกิดร่วมกับ unit mismatch ได้
จังหวะ capture ไม่ตรงสภาวะนิ่งจริง ถ้าจับตอนขึ้น-ลงแท่นหรือมีแรงถ่ายน้ำหนักบางส่วน ค่าที่ได้อาจเบี้ยว อาจทำให้บางเคสดูแปลก แม้หน่วยจะถูกต้อง
Vision metadata ผิดปกติ เช่น mask/geometry เพี้ยน ทำให้ข้อมูลประกอบบางส่วนเชื่อถือได้น้อยลง ไม่ใช่ต้นเหตุของน้ำหนักโดยตรง แต่ทำให้ debug ยากขึ้น

7) ข้อสรุปสำหรับคุยกับทีม

ตอนนี้หลักฐานโดยรวม หนุนสมมติฐานว่า interface อาจส่งค่าเป็น lb แล้วถูกตีความเป็น kg เพราะมันทำให้ทั้งเคสหน้างานบางเคส และ pattern ในชุดใหญ่กลับมาสมเหตุผลขึ้นมาก แต่ ยังไม่ควรปิดคดีที่สาเหตุนี้อย่างเดียว เนื่องจากยังมีหลาย session ที่แม้แปลงจาก lb แล้วก็ยังดูหนักเกิน plausibility จึงยังต้องตรวจสาเหตุร่วมอย่าง stale serial, tare/load ค้าง และ timing ของการ capture ต่อ

8) วิธีพิสูจน์หน้างานแบบสั้นที่สุด

  1. จับคู่ภาพหน้าจอเครื่องชั่งกับ raw serial payload เวลาเดียวกัน แล้วดูว่าข้อความจาก interface มี unit อะไรตามมาจริง
  2. ทดสอบชั่งแบบควบคุมจำนวนตัวหรือใช้น้ำหนัก known load แล้วเทียบค่า display กับค่าที่เข้า metadata พร้อมกัน
  3. เฝ้าดูค่าระหว่าง session ต่อ session ว่ามีการค้างหรือ reuse ค่าเดิมก่อนมีน้ำหนักรอบใหม่หรือไม่
