คู่มือ Onsite Release ของ Cloud Layer บน Ubuntu

เอกสารนี้ใช้สำหรับเครื่องหน้างานที่รันผ่าน Docker Compose และต้องการอัปเดตจากชุด release ที่ export ไปแล้ว

แนวทางนี้แยก artifact เป็น 3 bundle ชัดเจน: infra, cloud services, apps web

ใช้ `docker-compose.onsite.yml` ใช้ `docker compose up -d` หลีกเลี่ยง `--build`

สิ่งที่ต้องเข้าใจก่อน

ในโครงสร้างปัจจุบัน `dashboard-web` และ `admin-web` ถูกอ้างจาก `cloud-layer/docker-compose.yml` ผ่าน path ไปที่ `../apps` ดังนั้นเครื่องปลายทางควรมีโครงสร้าง source แบบนี้เสมอ

/srv/FarmIQ_V02/
  apps/
    dashboard-web/
    admin-web/
  cloud-layer/
    docker-compose.onsite.yml
    exports/
    scripts/
ถ้าถือไปเฉพาะ `cloud-layer` อย่างเดียว ระบบอาจยังขึ้นได้เมื่อ image ครบทุกตัว แต่จะเปราะมากทันทีที่มีการ build ใหม่หรือ operator เผลอใช้ไฟล์ compose ผิดตัว

Bundle มาตรฐานของ release

Bundle เนื้อหา
infra PostgreSQL, pgAdmin, Vault, RabbitMQ, Datadog agent
cloud-services Cloud services ทั้งหมดที่ build จาก `cloud-layer/*` รวมถึง metabase
apps-web dashboard-web และ admin-web

ขั้นตอนอัปเดตบน Ubuntu

1. ตรวจเครื่องเดิม

docker version
docker compose version
cd /srv/FarmIQ_V02/cloud-layer
docker compose ps

2. สำรองข้อมูลสำคัญ

mkdir -p ~/backup/cloud-layer-$(date +%F-%H%M)
cp .env ~/backup/cloud-layer-$(date +%F-%H%M)/.env.backup

docker exec -t farmiq-cloud-postgres \
  pg_dumpall -U farmiq \
  > ~/backup/cloud-layer-$(date +%F-%H%M)/postgres-all.sql

3. หยุด stack เดิมแบบไม่ลบ volume

docker compose down
ห้ามใช้ docker compose down -v ถ้ายังต้องการฐานข้อมูลและ state เดิม

4. อัปเดต source ให้ครบทั้ง `apps` และ `cloud-layer`

cd /srv
mv FarmIQ_V02 FarmIQ_V02.backup-$(date +%F-%H%M)
mkdir -p FarmIQ_V02

# คัดลอกชุดใหม่เข้า /srv/FarmIQ_V02
# ให้มีทั้ง apps/ และ cloud-layer/

5. โหลด image ทั้ง 3 bundle

cd /srv/FarmIQ_V02/cloud-layer/exports/onsite-release-YYYYMMDD-HHMMSS

docker load -i cloud-layer-infra-YYYYMMDD-HHMMSS.tar
docker load -i cloud-layer-cloud-services-YYYYMMDD-HHMMSS.tar
docker load -i cloud-layer-apps-web-YYYYMMDD-HHMMSS.tar

6. สตาร์ตด้วย compose สำหรับ onsite

cd /srv/FarmIQ_V02/cloud-layer
docker network inspect farmiq-net >/dev/null 2>&1 || docker network create farmiq-net
docker compose -f docker-compose.onsite.yml up -d

7. Verify หลังขึ้นระบบ

docker compose -f docker-compose.onsite.yml ps
curl http://localhost:5125/api/health
curl -I http://localhost:5142
curl -I http://localhost:5143

ข้อควรระวังสำคัญ

  • อย่าใช้ `docker-compose.dev.yml` หน้างานเมื่อมี release bundle อยู่แล้ว
  • อย่าใช้ `deploy full` บนหน้างาน ถ้าคุณไม่ได้ตั้งใจ rebuild image บนเครื่องนั้น
  • ถ้าจำเป็นต้องวาง source ในโฟลเดอร์ชื่ออื่น ให้ใช้ `COMPOSE_PROJECT_NAME=cloud-layer`
  • ถ้าบาง service ยังไม่ขึ้น ให้ไล่ infra ก่อน แล้วค่อย `feature-store`, `hybrid-router`, `api-gateway-bff`

Quick Flow

  1. Backup `.env` และ PostgreSQL
  2. `docker compose down`
  3. แทนที่ source ชุดใหม่ทั้ง `apps` และ `cloud-layer`
  4. `docker load` ทั้ง 3 bundle
  5. `docker compose -f docker-compose.onsite.yml up -d`
  6. เช็ก health และหน้า web

คำสั่งที่แนะนำ

cd /srv/FarmIQ_V02/cloud-layer
docker compose down

cd /srv/FarmIQ_V02/cloud-layer/exports/onsite-release-YYYYMMDD-HHMMSS
docker load -i cloud-layer-infra-YYYYMMDD-HHMMSS.tar
docker load -i cloud-layer-cloud-services-YYYYMMDD-HHMMSS.tar
docker load -i cloud-layer-apps-web-YYYYMMDD-HHMMSS.tar

cd /srv/FarmIQ_V02/cloud-layer
docker compose -f docker-compose.onsite.yml up -d
docker compose -f docker-compose.onsite.yml ps

Rollback แบบเร็ว

  1. `docker compose -f docker-compose.onsite.yml down`
  2. สลับกลับไปใช้โฟลเดอร์ backup เดิม
  3. สั่ง `docker compose -f docker-compose.onsite.yml up -d` จากชุดก่อนหน้า
