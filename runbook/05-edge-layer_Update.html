คู่มืออัปเดต Edge Layer หน้างานบน Ubuntu

คู่มือนี้ออกแบบมาสำหรับกรณีที่เครื่องหน้างานมี docker compose รันอยู่แล้ว และต้องการอัปเดต edge-layer แบบปลอดภัย โดยเน้นวิธีที่ใช้ image tar ที่เตรียมมาจากนอกหน้างานเป็นหลัก เพื่อหลีกเลี่ยงการ build ใหม่บนเครื่อง Ubuntu โดยไม่จำเป็น

อ้างอิงจาก: edge-layer/README.md
ระบบเป้าหมาย: Ubuntu Linux
อัปเดตเอกสาร: 2026-08-20

สรุปสั้นก่อนลงมือ

  1. ยืนยันก่อนว่าชุด image tar ที่ถือไป เป็นของ edge-layer จริง
  2. สำรองไฟล์ .env และบันทึกสถานะ compose เดิมไว้ก่อน
  3. ในเคสนี้ postgres รันอยู่ใน Docker Compose ชุดเดียวกันกับ service อื่น ๆ ของ edge-layer
  4. ดังนั้นให้ใช้ docker-compose.yml คู่กับ docker-compose.dev.yml เหมือนเดิม
  5. หยุด stack เดิมด้วย docker compose down เท่านั้น ห้ามใช้ down -v ถ้ายังต้องเก็บข้อมูล
  6. อัปเดตโค้ดในโฟลเดอร์ edge-layer
  7. โหลด image tar ใหม่ด้วย docker load -i ...
  8. รัน ./scripts/deploy.sh validate แล้วใช้ docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
  9. เช็ก docker compose ps, health check และ logs ก่อนส่งมอบ
ตัวอย่างไฟล์ export สำหรับอัปเดต edge-layer แบบ offline:
D:\FarmIQ_RawData_to_TrainModel\Code-Edge-PRD\FarmIQ_V02\edge-layer\artifacts\docker-images\edge-layer-images-20260816.tar

เช็กลิสต์ก่อนออกหน้างาน

  • โฟลเดอร์โค้ดชุดใหม่ของโปรเจกต์ หรือ zip/tar ที่แตกได้บน Ubuntu
  • ไฟล์ image tar ของ edge-layer
  • ค่า .env ของหน้างาน หรืออย่างน้อยสำเนาของไฟล์เดิม
  • สิทธิ์ใช้ sudo docker บนเครื่อง Ubuntu
  • พื้นที่ว่างพอสำหรับไฟล์ tar และ image หลัง load
  • เวลาสำหรับตรวจหลัง deploy อย่างน้อย 10-20 นาที

คำสั่งหลักที่ใช้บ่อย

./scripts/deploy.sh validate
./scripts/deploy.sh up
./scripts/deploy.sh ps
./scripts/deploy.sh logs edge-ingress-gateway
./scripts/deploy.sh down

แนวทางที่แนะนำ

ถ้าหน้างานเป็น Ubuntu และคุณมี image tar ไปด้วยแล้ว ให้มองงานนี้เป็น การอัปเดต release มากกว่า การ build โค้ดบนเครื่องหน้างาน นั่นคือ:

  • อัปเดตไฟล์ compose, scripts, docs, env และ source code ในโฟลเดอร์ edge-layer
  • ใช้ docker load เพื่อเอา image ที่ build มาแล้วขึ้นเครื่อง
  • ในเคสนี้ database PostgreSQL อยู่ใน compose stack เดียวกันกับ service อื่น ๆ จึงต้องยก stack ด้วย docker-compose.yml คู่กับ docker-compose.dev.yml
  • ใช้ docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d เพื่อให้ container ใหม่ขึ้นจาก image ที่โหลดไว้
อย่าใช้ up -d --build บนเครื่องหน้างานโดยอัตโนมัติ ถ้าจุดประสงค์คือ deploy จาก image tar เพราะมันจะพยายาม build ใหม่จาก source และอาจพังได้จาก dependency, network, apt, npm, หรือ cache ที่หน้างานไม่พร้อม
ถ้า database ไม่ได้รันใน Docker Compose แต่เป็น PostgreSQL ที่ติดตั้งตรงบน Ubuntu host ต้องทำ compose override เพิ่มเพื่อเปลี่ยน DATABASE_URL ของ service ต่าง ๆ ให้ชี้ไป host DB จริง เพราะค่าเดิมใน compose ชุดนี้อ้างไปที่ service ชื่อ postgres ภายใน compose network

เลือกแนวทางให้ตรงกับฐานข้อมูลเดิม

สถานการณ์ แนวทางที่ควรใช้
Database เดิมรันเป็น container อยู่บนเครื่องหน้างาน และอยู่ใน compose stack เดียวกันกับ edge services ใช้ docker-compose.yml + docker-compose.dev.yml ตามเดิม และหยุดทั้ง stack ด้วย down แบบไม่ใส่ -v
Database เดิมติดตั้งตรงบน Ubuntu host อย่าใช้ compose ชุดเดิมตรง ๆ ต้องมี override เพิ่มเพื่อเปลี่ยน DATABASE_URL ของทุก service ให้ชี้ไป host database จริง

ขั้นตอนปฏิบัติจริงบน Ubuntu

Step 1: เข้าเครื่องและยืนยัน path ที่ใช้งานจริง

สมมติว่าโค้ดอยู่ที่ /opt/FarmIQ_V02 ให้เปลี่ยน path ให้ตรงกับเครื่องจริงก่อนเสมอ

export RELEASE_ROOT=/opt/FarmIQ_V02
export EDGE_HOME=$RELEASE_ROOT/edge-layer

cd "$EDGE_HOME"
pwd
ls

Step 2: เก็บหลักฐานก่อนอัปเดต

ถ้าเครื่องเดิมกำลังรันผ่าน docker compose อยู่ ให้บันทึกสถานะไว้ก่อน จะช่วยมากเวลาเทียบก่อน-หลังหรือ rollback

cd "$EDGE_HOME"

mkdir -p ~/farmiq-update-backup/$(date +%F)
docker compose -f docker-compose.yml -f docker-compose.dev.yml ps \
  > ~/farmiq-update-backup/$(date +%F)/edge-ps-before.txt

docker compose -f docker-compose.yml -f docker-compose.dev.yml config --images \
  > ~/farmiq-update-backup/$(date +%F)/edge-images-before.txt

cp .env ~/farmiq-update-backup/$(date +%F)/edge.env.backup
เคสนี้ตรงกับโครงสร้างปัจจุบันของ repo โดยตรง เพราะ service ต่าง ๆ อ้าง DB เป็น postgres ใน compose network เดียวกัน และตัว postgres เองก็เป็น service ภายใน stack เดียวกัน

Step 3: ถ้าต้องการ rollback ง่าย ให้ backup image เดิมไว้ก่อนโหลดชุดใหม่

ขั้นตอนนี้เป็น optional แต่แนะนำมากถ้าหน้างานมีความเสี่ยงสูงและไม่มีเวลานั่ง build ใหม่

cd "$EDGE_HOME"

docker image save -o ~/farmiq-update-backup/$(date +%F)/edge-current-images-backup.tar \
  $(docker compose -f docker-compose.yml -f docker-compose.dev.yml config --images)

Step 4: หยุด stack เดิมแบบไม่ลบข้อมูล

จุดนี้สำคัญมาก ถ้ายังต้องเก็บฐานข้อมูลหรือข้อมูลใน volume เดิม ห้ามใส่ -v

cd "$EDGE_HOME"
./scripts/deploy.sh down

# หรือใช้ compose ตรง
docker compose -f docker-compose.yml -f docker-compose.dev.yml down
ในเคสนี้คำสั่ง down จะหยุดทั้ง postgres และ service อื่นใน stack เดียวกัน แต่ยังเก็บ volume ข้อมูลไว้ให้ ถ้าเผลอใช้ down -v มีความเสี่ยงลบข้อมูลฐานข้อมูลเดิม

Step 5: อัปเดตโค้ดชุดใหม่ลงเครื่อง

แนวทางที่ปลอดภัยคือเก็บโฟลเดอร์เดิมไว้ก่อน แล้วคัดลอก release ใหม่ลง path เดิมหรือ path ใหม่ที่วางแผนไว้ จากนั้น restore .env เดิมกลับมา

# ตัวอย่างแนวคิด
cd /opt
mv FarmIQ_V02 FarmIQ_V02_before_2026-08-20

# แตก release ใหม่
tar -xvf FarmIQ_V02_release.tar

# เอา env เดิมกลับมา
cp FarmIQ_V02_before_2026-08-20/edge-layer/.env FarmIQ_V02/edge-layer/.env
ถ้าคุณไม่ได้เปลี่ยนทั้ง repo แต่อัปเดตเฉพาะ edge-layer ให้ย้ายเฉพาะโฟลเดอร์นั้นก็ได้ แต่ต้องระวัง file ownership, permission และไฟล์ config ที่หน้างานแก้ไว้เอง

Step 6: โหลด image tar ของ edge-layer

ตัวอย่างนี้ใช้ไฟล์ tar ที่ export มาแล้วของ edge-layer

cd /opt/packages
ls -lh edge-layer-images-20260816.tar

docker load -i edge-layer-images-20260816.tar

หลังโหลดเสร็จควรเช็กว่ามี image ของ edge-layer ครบ

docker image ls | grep '^edge-layer-'

Step 7: validate ก่อนยก container

ใช้ script ที่มีอยู่ใน repo เพื่อเช็ก compose และ script ที่จำเป็นก่อน

cd "$EDGE_HOME"
chmod +x ./scripts/deploy.sh
./scripts/deploy.sh validate

ถ้าต้องเปิด profile feed-intake ด้วย ให้ใช้:

./scripts/deploy.sh validate --with-feed-intake

Step 8: ยก stack ใหม่ขึ้น

ถ้าต้องการใช้ image ที่โหลดไว้ และ database เดิมคือ postgres ที่รันอยู่ใน Docker Compose ชุดเดียวกันกับ service อื่น ให้ใช้ compose สองไฟล์เดิมนี้โดยไม่ใส่ --build

cd "$EDGE_HOME"
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d

# ถ้าอยากใช้ script มาตรฐานเดิมของ repo
# ให้ระวังว่า script นี้ปัจจุบันใช้ up -d --build
# เหมาะกับเครื่องที่พร้อม build มากกว่าเครื่องหน้างานแบบ offline
ถ้าคุณต้องการ deploy จาก image tar อย่างเดียว ผมแนะนำให้ใช้คำสั่ง docker compose ... up -d ตรง ๆ แทน ./scripts/deploy.sh up เพราะ script ปัจจุบันจะพ่วง --build
สรุปสำหรับเคสของคุณ: postgres เป็นส่วนหนึ่งของ compose stack เดียวกันกับ edge services ดังนั้นต้องใช้ docker-compose.dev.yml ด้วยครับ และไม่ควรรันเฉพาะ docker-compose.yml ตัวเดียว

Step 9: ตรวจสถานะหลัง deploy

cd "$EDGE_HOME"
docker compose -f docker-compose.yml -f docker-compose.dev.yml ps

curl http://localhost:5103/api/health
curl http://localhost:5113/api/health
curl http://localhost:5107/api/health

ถ้าตัวไหนไม่ขึ้น ให้ดู logs เฉพาะ service

docker compose -f docker-compose.yml -f docker-compose.dev.yml logs --tail=200 edge-ingress-gateway
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs --tail=200 edge-sync-forwarder
docker compose -f docker-compose.yml -f docker-compose.dev.yml logs --tail=200 edge-vision-inference

สิ่งที่ต้องระวังเป็นพิเศษ

เรื่อง คำแนะนำ
ใช้ image ผิดชุดหรือผิด tag ก่อน docker load ให้ยืนยันชื่อไฟล์ tar และหลัง load ให้เช็ก docker image ls | grep '^edge-layer-' เพื่อให้แน่ใจว่าเป็น image ของ edge-layer ที่ต้องการใช้งานจริง
ข้อมูลหาย อย่าใช้ docker compose down -v เว้นแต่คุณตั้งใจลบ volume และข้อมูลจริง ๆ
build บนหน้างาน ถ้าไม่มีเหตุจำเป็น อย่าใช้ --build บนเครื่องหน้างาน เพราะเวลาล้มมักล้มจาก network หรือ dependency ภายนอก
ค่า .env ของหน้างาน อย่า overwrite ไฟล์ .env ของหน้างานทิ้งโดยไม่เช็ก เพราะอาจมีค่าที่ผูกกับ cloud, tenant, API key, หรือ network ของไซต์จริง
path ของ compose เดิม ควรหยุด stack จากโฟลเดอร์โปรเจกต์เดียวกับที่ใช้งานจริง หรืออย่างน้อยใช้ compose file ชุดเดียวกัน เพื่อไม่ให้มี container ค้างคนละ project

กรณี rollback

ถ้าหลังอัปเดตแล้ว service ขึ้นไม่ครบ ให้ rollback แบบง่ายที่สุดดังนี้

cd "$EDGE_HOME"
docker compose -f docker-compose.yml -f docker-compose.dev.yml down

docker load -i ~/farmiq-update-backup/2026-08-20/edge-current-images-backup.tar

# restore โค้ดหรือโฟลเดอร์เดิมกลับมา
cd /opt
rm -rf FarmIQ_V02
mv FarmIQ_V02_before_2026-08-20 FarmIQ_V02

cd /opt/FarmIQ_V02/edge-layer
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d

เอกสารนี้ทำขึ้นเพื่อใช้หน้างานจริงบน Ubuntu โดยเน้นการอัปเดต edge-layer จาก image tar และ compose เดิมที่มีการใช้งานอยู่แล้ว หากต้องการ ผมสามารถทำเวอร์ชันถัดไปให้เป็นรูปแบบ checklist 1 หน้า หรือเพิ่ม section สำหรับ "offline only", "with feed-intake", และ "cloud connected" แยกกันได้อีกครับ
